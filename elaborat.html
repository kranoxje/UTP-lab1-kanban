1. Кои алатки ги одбравте за споредба?

Разгледав три бесплатни алатки што овозможуваат Kanban табла и јавно споделување преку линк:

  1. Trello (Atlassian) — препорачана на вежбата.
  2. GitHub Projects / GitHub Issues — веќе ја користам за лабораториски вежби (профил kranoxje).
  3. KanbanFlow — едноставна веб-алатка со вграден Pomodoro и WIP лимити.

2. Главни карактеристики, силни и слаби страни

Алатка Главни карактеристики Силни страни Слаби страни
Trello Листи и картички, етикети, рокови, checklists, Power-Ups, Butler автоматизација, јавен линк на табла, календар. Најлесна за учење; визуелно јасна; многу интеграции; бесплатниот план е доволен за лична табла. Напредна аналитика (Dashboard, Timeline) е на платените планови; WIP лимит не е првокласен на Free.
GitHub Issues како картички, ознаки како колони, Projects табла, GitHub Actions, Insights, јавен репозиториум и Pages линк. Сè е јавно преку линк; историја на промени; интеграции преку Actions; погодна ако веќе се работи код/лаб. UI-то е повеќе „развојно“ отколку „табла за поддршка“; Projects бара дополнителни дозволи; помалку „drag-and-drop“ едноставност од Trello.
KanbanFlow Колони со WIP, вграден тајмер, Swimlanes, јавен read-only линк, основни извештаи за време по колона. WIP лимитот е вграден; добра за личен фокус; брз старт. Помалку интеграции; изгледот е поедноставен; бесплатниот план има ограничувања кај тимски функции.

3. Која алатка ја одбравте и зошто?

Ја одбрав GitHub (јавен репозиториум + Issues + GitHub Pages) како хост на личната табла.

Причини:

  • Веќе имам активен GitHub профил (kranoxje) поврзан со индекс 233295 (репозиториуми SI_2024_lab1_233295 и сл.).
  • Јавниот линк е стабилен и лесно се проверува од Incognito: Pages URL + јавни Issues.
  • Интеграциите (GitHub Actions) и аналитиката (Insights / Actions лог) се достапни на бесплатниот план, што е потешко кај Trello Free.
  • Картичките се Issues — можам да ги дополнувам цел семестар, со опис, етикети и коментари, што се оценува на крајот на курсот.

Разлика од останатите: Trello е поудобна за чисто визуелно влечење картички, а KanbanFlow има почист WIP, но GitHub ми дава јавен линк, историја и интеграција без платен план. За предмет поврзан со техничка поддршка, Issue како „тикет“ е блиску до реален service-desk работен тек.

4. Функционалност што би ја додале во сопствена Kanban алатка

Неопходна функција за издвојување: автоматски SLA часовник на картичката.

Секоја картичка би имала приоритет (P1–P4) и цел за прв одговор / решавање. Таблата би обојувала картички што се блиску до истек и би забранувала влечење нова P1 во „Во тек“ ако WIP-от е полн — освен со експлицитна ескалација. За техничка поддршка ова е поважно од уште еден календар: се гледа дали тимот го прекршува договореното време, не само дали задачата е „некаде на таблата“.

6. Колони и почетен WIP лимит

Почетни колони:

  1. Backlog — идеи и задачи што уште не се подготвени.
  2. Ready — јасно дефинирани, можат да се земат веднаш.
  3. Во тек (In Progress) — активно се работи. WIP = 2.
  4. Блокирано — чека информација / зависност. WIP = 1 (да не се крие работата тука).
  5. Завршено — готово; останува за доказ на активност.

Како дојдов до WIP = 2. Предметот е еден од неколку во семестарот. Ако во „Во тек“ ставам повеќе од две картички (на пр. елаборат + читање + следна лаб + консултации), се префрлам меѓу задачи и никоја не се затвора. Две истовремени ставки: една „обврска со рок“ и една „учење/подготовка“. Ако се појави итна задача, прво се довршува или се паркира во Backlog/Blocked, наместо да се крши лимитот. Лимитот е почетна хипотеза — ќе го корегирам ако на аналитиката се види постојан сообраќаен метеж пред Ready.

7. Дополнителна интеграција

Овозможив GitHub Actions како интеграција: при секоја промена на Issues се генерира краток аналитички збир (број картички по колона). Тоа е еквивалент на Power-Up: таблата се поврзува со автоматизација надвор од рачното влечење картички.

Дополнително, јавниот GitHub API ја полни визуелната табла на Pages — интеграција „Issues → Kanban приказ“.

8. Аналитика и распределба на задачи

GitHub нуди:

  • Insights на репозиториумот (активност, затворање на Issues).
  • Actions лог со број на отворени/затворени картички по етикета.
  • На самата табла: бројач и црвена рамка ако WIP на „Во тек“ е над 2.

Како помага: ако Insights покаже дека картичките долго стојат во Ready, земам премногу задачи на залиха. Ако „Во тек“ често е преку лимитот, го намалувам влезот од Ready. Ако Blocked расте, прво ги отстранувам пречките (прашање до предметниот, материјал) наместо да отвораам нови задачи. За техничка поддршка ова е исто како да гледаш редица тикети и старост на тикет, не само број.

Trello Dashboard / KanbanFlow time reports прават слично, но на Free кај Trello се ограничени; затоа Actions + WIP бројач ми се доволни за лична употреба.

  • Споредба на три Kanban алатки — Done

  • Лабораториска вежба 1 — елаборат — In Progress
  • Поставување на јавната табла — In Progress (WIP = 2, полн слот)
  • Читање: процеси на техничка поддршка — Ready
  • Прашања за консултации — Ready
  • Подготовка за лабораториска вежба 2 — Backlog
  • Повторување на материјал од предавања 1–2 — Backlog

Секоја картичка има краток опис (што значи „готово“) и етикета (лаб-1, предавања, аудиториски…).
